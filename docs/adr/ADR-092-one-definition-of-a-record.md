## Decision

1. **One definition, in Python.** `plugin/lib/record.py` gains `recognised_as_record(path, text, root)`, returning whether the file is a record and the parts a caller reports: the Status value read, whether the file sits where records are kept, and which arm admitted it. **No file is a record, by either arm, when a directory named `templates` (ASCII case-insensitive) is on its path as listed or on its placed path** (the owner, 2026-10-07: a template is never a record, whatever its name; the same file outside `templates/` is judged as any other). Both paths are asked, so a link under `templates/` to a record elsewhere is not a record under its `templates/` spelling, and a link elsewhere to a file under `templates/` is not one either (layouts L7 and L8). Outside such a directory, a file is a record when its name starts `ADR-<n>` (`_NUMBERED_REF`, any width) or `spec-<n>` (`spec[-_]?\d`, `re.I`), whatever its directory. Otherwise it is a record by content when it carries a Status (ADR-074 Decision 1) and a `## Context` or `## Decision` heading on one line, is not named `README.md` in any case, and either has a line-start `**Status:**` or is kept where records are (a directory `_RECORD_DIRECTORY` names, never under `tasks/`). A heading is one line: `_RECORD_SECTION`'s gap after `##` becomes whitespace that is not a line break (`\r`, `\n`, the breaks `split_lines` knows), so `##` alone on a line followed by `Decision` is no heading, as `_sections` already reads it (row R34). This is adr-lint's rule today with three narrowings of ADR-074 Decision 5. The `templates` one covers both arms, so `templates/ADR-001-x.md` is not a record (row R29). **A `README.md` is a catalog, never a record by content** (the owner, 2026-10-07), as adr-retire-check already decides (:158); the name arms cannot match it. Outside `templates/`, a record named `ADR-<n>` keeps every finding it had. Measured 2026-10-07 by listing the directory: the plugin's own `plugin/templates/` holds `adr-archive-readme-template.md`, `adr-template.md`, `architecture-template.md`, `spec-template.md`, `task-template.md` and `tasks-readme-template.md`; none starts `ADR-<n>` or `spec-<n>` or matches lifecycle's `ADR_FILE` (each needs a digit after the prefix), so no reader reads any of them as a record by name today, and the only verdict that changes there is adr-lint's on `adr-template.md`, recognised today by its `**Status:**` line and headings.
   **Amended 2026-10-07 (an outside probe run found a gap review inside a record's own directory read as a record):** kept where records are also excludes a file inside another record's own directory below the record directory, one ADR-063 gives an identity (a bare number such as `2024/` is a year, not one), so `docs/adr/ADR-132/GAPS.md` with a `## Status` section and a `## Decision` heading is no record (row R45). The file's own folder is not another record's: `docs/adr/0048-x/0048-x.md` is kept (row R48). A name arm still admits a file named `ADR-<n>` there.
2. **Placement is one rule, whoever asks and however the path is spelled.** The file's real path relative to the real git root; when the real path leaves the root, the path as listed relative to the root; when there is no root, the path's own components. adr-lint no longer answers differently for a relative and an absolute spelling of the same file (finding 1).
3. **Eligibility is one rule for every corpus walk, and it is not the definition.** A walk (adr-retire-check, lifecycle's discovery, work-next's candidates) considers a path only when its basename ends `.md` in any case, on every platform; it is not `README.md` in any case; and no directory between the walked root and the file is `tasks` (ADR-063 Decision 4), `templates` (Decision 1, so a template is not even a `notRead` candidate) or a fixture tree (`uninteresting.mjs`'s pattern, which record.py gains as `UNINTERESTING_DIRECTORY`). adr-lint, judging a path named on its command line, applies the definition without eligibility, because it must lint a fixture named directly; the definition already rejects every path under `templates/`. The promise this record makes (a file adr-lint lints is counted or named by every corpus reader) is over eligible paths: a name-arm file under `tasks/` or in a fixture tree is linted when named and enumerated by no walk, as today.
4. **Every Python reader calls the definition.** adr-lint calls it for its verdict and its message. adr-retire-check counts **the recognised records that have an ADR-063 identity**, and advises on **every recognised record without one**, the name arm included (`ADR-12345-x.md`, `spec-01-x.md`, `decision.md`), never counting and never dropping it. adr-next's `owning_record` reads an unrecognised file as found with no Status, and a file that exists and is not a regular file as found and unreadable. `looks_like_record` is deleted. adr-retire-check's duplicate-identity error stays, since a sealed archive reachable twice is the layout defect it names, and says so when the paths are one file on disk.
5. **lifecycle's JS is its only mirror, with two sets.** The **discovery set** is every eligible path that is named like a record (`ADR_FILE`, or a name arm at any width with Python's `re.I` and `\d` reproduced, so `ſpec-01` and a non-ASCII digit read alike), or sits under a record directory, or passes the **content screen**: a streamed read of the whole file, at any size, that finds both a line starting `**Status:**` and a line `_RECORD_SECTION` matches. Because Decision 1 makes a heading one line, the screen is exact, not a guess: outside a record directory the content arm cannot admit a file lacking either line. The screen is bounded the way the record budget is (lifecycle.mjs:2631-2636): past 64 MiB streamed in one `adrCorpus` call it stops, the first path left unscreened is named as unexamined, and the look is PARTIAL, never `look ok` over a tree it did not read; the budget is an `adrCorpus` option so a test can cross it cheaply. Dedup (Decision 7) runs over the discovery set. The **counted set** is each kept path the mirror recognises, read under the existing 512 KiB record budget; a path over it is `unreadable` and PARTIAL, as a record is today. A discovered path the mirror does not recognise is in `notRecognised` only when it was discovered by name; one discovered by place or by the screen and not recognised was never claimed, and no reader names it, as today. A path whose read failed is never dropped: one discovered by name or by place is `unreadable` and PARTIAL, as today; one that only the screen could have admitted is `unreadable` and PARTIAL for every failure except its absence from the working tree (`ENOENT`), which is an observation that it carries nothing.
6. **The approved answers.** `tests/fixtures/record-recognition.json` holds the rows below, and each row is read by every reader its columns name. The expected answers are these, approved with this record. No task may change one; a task that finds a reader disagreeing stops and asks. Each task asserts only the columns it makes true, by exact equality over every row and layout that has a cell in that column (`deepStrictEqual` of the whole row-id → answer map, so a dropped row fails); a row that needs a link (R1, L1-L4, L7, L8) is asserted in a companion test that may skip only on Windows when the link cannot be made, L5 in the regular-file tests and L9 in the not-text tests. `P` is `Status: Accepted`, `B` is `**Status:** Accepted`, `D` is `## Decision`, `C` is `## Context`. adr-retire-check's `adr_files` is called with the row path's first component as its root (`adr`, `docs`, `Final`, `notes`, `plugin`, `tests`), through the module loader the tests already use (`load_script`, tests/gate-regressions.py:716), so eligibility is judged below that root. `—` means the reader lists the path nowhere; `undecided` is the undecided rule's answer.

7. **Dedup prefers, in order:** a spelling a name arm recognises; then fewer links, counted by resolving each hop; then the first listed. The order is strict: the name preference is decided first, so a name-arm spelling wins over any other spelling whatever either one's link count, and link counts are compared only between two spellings the name preference cannot separate. The name preference is computed from the name alone, so it is known before any read. Only `adrCorpus` passes it. Task directories (lifecycle.mjs:1487, work-next.mjs:265) take no name preference and gain the per-hop count, which changes their winner only where a path's links were undercounted. `linksIn(file, limit = 32)` counts every link component of the path and every link met while resolving a target, a link met twice counting twice (`a/a/file.md` with `a` → `.` counts 2), and stops when the count reaches the limit: that path counts as unbounded (`Infinity`), which loses to every counted path in the same name class, and two unbounded paths keep the first listed. `onceByRealPath` takes the limit as an option so a test can reach it with a short chain. A path whose real path cannot be taken (a cycle makes `realpathSync` throw) is kept, as today (lifecycle.mjs:1390).
8. **No code-block line is a Status.** Indentation is measured in columns, a tab advancing to the next multiple of four: a line indented four or more columns (`    x`, a tab, ` \tx`, `  \tx`, `   \tx`) is never a Status label, bullet or `## Status` section value, and one indented at most three columns (`   x`) is read as today (T5's twins). A `## Status` section's value is its first non-empty line **outside any fence inside the section**, a fence's own marker lines included, so `Accepted` between two fence markers, indented or not, is no value; a section with no such line reads `""`, an empty Status, as record.py:776 reads one today, and a text with no `## Status` section and no label reads `null` (rows R2, R35, R36; T5 asserts the two apart). **The frontmatter is delimited before any fence is scanned, in a whole document only**: `unfenced_numbered` takes whether its lines are a whole document, `record_status`, `_scan` and lifecycle's `fencedLines` pass a document, and `unfenced_lines` over a section's lines (adr-lint's Verification and Mutation Logs, adr-lint:1867, :1886) does not, so a log section opening with a `---` rule keeps its fenced example hidden. A fence opened inside a YAML value then hides nothing below the block. This changes the one fence walk (`_scan` / `unfenced_numbered` and `fencedLines`), so every section reader gains it.
9. **Every numbered candidate is counted or named.** A candidate is an eligible tracked `.md` file with a numbered basename (`^[A-Za-z]*-?\d{2,}[-_]`) that sits in a record directory, has a letter prefix before its number (`RFC0001-`), or carries a Status in any form. The first two are decided by the path; the third needs the content, read whole up to the corpus reader's 512 KiB. A candidate no reader counts is in `notRead`. A candidate decided by the path whose read failed (absent, unreadable, not a regular file) is in `partialBecause`. A path whose candidacy needs content is in `partialBecause` when the content could not be read for any reason but absence, or is over 512 KiB. Either makes `look` PARTIAL.
   **Amended 2026-10-07 (the owner, on a corpus of numbered `.rst` records with an RST Status section):** a numbered `.rst`, `.adoc` or `.txt` file in a record directory is a candidate too, in a format no reader parses: it is named in `partialBecause` with that reason, which makes the look PARTIAL, and it is never parsed; corpus-probe lists it as unread, so an attestation counts it in `notCompared` (row R46). One whose identity is a record the corpus counts is that record's attachment (`ADR-001-attachment.txt`, a layout adr-retire-check seals), and is not named; this exception is the executor's, pending the owner's word. In a record directory a number of any width makes a candidate (`1-intro.md` beside the records was named nowhere: a coordinator's note, 2026-10-07); elsewhere it is still two or more digits. A dated name in a record directory is a candidate by its path like any other numbered one, so a dated note, a dated companion and a dated file whose Status is prose are each named (rows R42-R44).
10. **Only a regular file holding text is read as a record**, by every reader in this class; anything else is could-not-look and named: adrCorpus `unreadable` and PARTIAL, work-next `partialBecause`, adr-retire-check could-not-run at exit 2, adr-next found and unreadable. Two reads, two guards: `read_regular(path)` refuses a path that is not a regular file and is used by every read, attribution included; `read_record_text(path)` adds the refusal of a NUL byte and is used only where text is read as a record (adr-retire-check's `adr_files` recognition and `status_of`, adr-next's owner read). adr-retire-check's `adr_id_for_file` reads through `read_regular` alone and never asks the content arm of NUL text, so a binary attachment (`notes-ADR-001.png`, or one under `ADR-001-x/`) is still attributed by its name and hashed raw into its unit's seal (adr-retire-check:191-198, :348-350, :368-369). adr-lint shares only the regular-file guard (`refuse_irregular` asks `read_regular`'s rule), so a NUL-bearing record still reaches `check_adr` and FAILs as text no gate can read (adr-lint:1064-1072, layout L9), and a directory named on its command line keeps its usage sentence at exit 1 (adr-lint:6436-6471), which names the directory and is not a verdict about any record. A directory a walk could not list is named the same way: in every adr-retire-check walk (T2: `adr_files`, `meaningful_obligations`, and the decision-unit walks at :346 and :348, where an unlisted directory is could-not-run rather than a digest over part of a unit) and in every other `walk` caller (T7), whose record reads go through `read_regular` too, so adr-debt (:480-482) no longer opens a FIFO. Every `*.md` walk reads `.md` in any case: adr-retire-check's (:156, :223) in T2, adr-debt's (:309, :480) and adr-verify's (:2444) in T7, so a `.MD` record's obligations and tasks are not missed off Windows.
11. **The unmarked-archive heuristic follows the definition where it can afford to.** Through `adrCorpus`, an archive-named directory with no Lifecycle marker is named exactly when it holds a record `adrCorpus` counted or held as undecided, or a task file; the name test is not consulted there, so `archive/001-note.md` holding no record names nothing. The two SessionStart callers (lifecycle.mjs:1814, :3744) open no record content, by CLAUDE.md §19 (they still read an archive's README for its Lifecycle marker, lifecycle.mjs:1305-1310, as today), and keep the name test, widened to the name arms (`ADR-<n>` at any width, `spec-<n>`); a record-shaped name there names its directory as advice, which is the stated limit of a test that reads no content. Neither path names a directory for a file under `templates/`, and a listed README carrying the marker freezes the directory in both.
12. **A fenced example is not a discriminator.** The content arm's line-start `**Status:**` and its `## Context` / `## Decision` heading are read only from lines outside every fence of the whole document (the one fence walk, Decision 8), never by a raw search over the text (adr-lint:6509-6510 today); the screen of Decision 5 keeps the same fence state as it streams. So a fence quoting a record's shape does not make a note a record (rows R37, R38), and a real record holding such an example still is one (R39).
13. **One title reading.** A record's title, from which ADR-063 Decision 1 takes its number, is its first `# ` heading outside a leading frontmatter block and outside every fence: `title_line` (record.py:631-636) and lifecycle's `titleLine` (:1975-1978) take adr-lint's `_record_title` rule (adr-lint:4197-4214), and adr-lint's `adr_numbers` (:6340-6348) reads its title number through that one reading, so a YAML comment or a fenced `# ADR-…` example never decides identity and never reports a false name/title mismatch (rows R40, R41). ADR-063's order (title, then name) is unchanged; what counts as the title is narrowed to a real heading.
14. **Discovery follows placement.** Decision 2 places a file where its real path lands; discovery asks the same question. An eligible listed path is under a record directory, for Decision 5, when its listed directory or its placed directory (the real path of its directory, taken once per listed directory) is one, so a listed link outside a record directory to a record in one is discovered and counted under its listed spelling, as adr-lint and adr-retire-check already read it (layout L10). A directory whose real path cannot be taken is read as listed, and the file is still discovered by name or by the screen.

The decision fails, and the parity test says so, if any row reads differently from its approved answer in any reader, if an eligible file adr-lint lints is counted, held undecided or named by no corpus reader, or if a file a reader counts is one adr-lint rejects. The data that could produce that failure exists today: the twelve inputs are rows R1-R17 and layouts L1-L6, and the second review's are rows R34-R36 and layouts L5, L7-L9.

## Alternatives Considered

- **Patch each reader separately**, as the review lists them: rejected because that is how the class arose. Six recognition rules already exist; a twelfth patch makes a seventh, and the next corpus shape finds the next disagreement.
- **Generate lifecycle's JS from the Python definition**: rejected because the two languages differ exactly where the review found defects (`\s`, `^` under multiline, `re.I` folding, `\d`); a generator that translated regexes would carry those differences invisibly, while a hand mirror held by a parity table shows each one as a failing row.
- **Spawn Python from lifecycle for every candidate**: rejected because lifecycle runs on SessionStart and on every prompt's brief, where a Python process per file costs an adopter's session seconds on a corpus of hundreds (CLAUDE.md §19), and a missing `python3` would turn every corpus reader into could-not-look.
- **Make lifecycle the definition and have Python mirror it**: rejected because adr-lint is the gate a record is checked against, and the owner chose on 2026-10-07 that adr-lint's answer wins.
- **Count a record without identity in adr-retire-check under a synthetic id**: rejected because adr-retire-check's catalog is keyed by identity (ADR-063), and ADR-063 Decision 4 already chose advice for exactly this case.
- **Read only a 64 KiB head for discovery and candidacy**: rejected because a Status past the head is then could-not-look for every long file, which on this repository would make docs/specs/2026-09-11-one-record-grammar.md (67,005 bytes) PARTIAL in every session; the 512 KiB record budget and a streamed two-line screen answer exactly.
- **Exclude templates only from lifecycle**: rejected by the owner on 2026-10-07: both languages, one rule.

## Consequences

- **Positive:** an eligible file adr-lint lints is a file every corpus reader counts or names, and a file no reader counts is named; the next corpus shape that splits them is one failing row of one table.
- **Negative:** discovery streams every eligible `.md` outside record directories through the two-line screen, which costs a large repository more than reading record directories alone (this repository: 226 eligible files, docs/BACKLOG.md 1.45 MB); the screen's 64 MiB bound turns a tree past it into PARTIAL, not into a long SessionStart; T3 measures the SessionStart hook's time on this repository and the largest corpus fixture before and after, and stops if it grows by more than a quarter. adr-lint on the bundled ADR template now says not-recognised instead of FAIL; the protection against a placeholder record passing is kept by the same text outside `templates/`, which still FAILs. Measured 2026-10-07: the only tracked paths with a `templates` directory are plugin/templates/ (six `.md`) and plugin/evals/templates/ (`.yaml`), and of them only adr-template.md is recognised today.
- **Neutral:** changing the fence walk (Decision 8) changes what every section reader sees in a record whose frontmatter holds a fence marker; T5 measures how many such files this repository has.

## Out of Scope

- Reading RFC-style corpora outside a record directory as records (permanent: boundary: ADR-087 Out of Scope, and the owner's 2026-10-07 answer to its spec's Grill Log row 8 that naming is enough)
- A YAML parser for frontmatter (permanent: boundary: only top-level keys are read, line by line, as ADR-087 decided)
- Spawning Python from the JS readers (permanent: boundary: rejected under Alternatives for its per-session cost)
- Widening ADR-063's identity past four digits (permanent: boundary: identity is ADR-063's decision; a record it cannot identify is advised, never dropped, by Decision 4 here)

## Risks

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| The wider discovery makes a non-record in an adopter's tree a record (a report written with `**Status:**` and `## Decision`) | Med | Low | adr-lint already lints exactly those files, so the readers now agree with a verdict the adopter already sees; templates (by either arm) and READMEs (by content) are excluded by Decision 1 |
| Streaming every eligible `.md` slows SessionStart on a large tree | Low | Med | the 64 MiB screen bound (Decision 5); T3 measures the opened-file and streamed-byte counts and the SessionStart hook's time on this repository and on the corpus fixtures, dated, and stops if the time grows by more than a quarter |
| The fence-walk change moves a section reader's answer somewhere unseen | Low | Med | T5 enumerates the callers (103 lines in 9 files on 2026-10-07) and runs every catalogue entry in the edited functions |
| A tracked file deleted in the working tree turns a look PARTIAL | Low | Low | only a path decided by name or place does (Decision 9, L6); a path only content could admit is observed absent |
| A locked test's behaviour changes | Med | Low | each task asks `scripts/test-locks.py` first; a locked test stays byte-identical and a new test goes beside it, or the task stops |
