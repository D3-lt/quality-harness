The other half of a good fence, and the reason a wide filter is not automatically
right: the command must still be RED before the work exists.

PASS when the answer guards against a vacuous pass — a `-run` pattern that
matches nothing exits 0 in Go, so a guard on `no tests to run` / `=== RUN`
output, or an explicit statement that the pattern is checked to match, both
count.

FAIL when the fence would exit 0 with no tests executed and the answer says
nothing about it.
FAIL when there is no runnable command in the answer.

This grader exists so the case cannot be won by widening the filter alone. A
fence that runs everything and a fence that runs nothing both score badly here
for opposite reasons.
